# dental

Запись к стоматологу в Telegram: бот и Mini App для врача — расписание на день, новые
записи без двойного бронирования, напоминания пациентам в WhatsApp, утренняя сводка.

Учебный проект. Сейчас только **тестовые пациенты**: реальные данные — после шага 8
(регистрация в реестре ГАЗПД, согласие пациента, проверка по главе 11 Цифрового кодекса КР).

## Стек

Spring Boot 4.1, Java 25, Postgres 18, Flyway, Testcontainers. Mini App — HTML и JS без сборки.

## Запуск

- Нужны JDK 25 и Docker.
- `./mvnw spring-boot:run` — профиль `local`; Postgres из `compose.yaml` поднимается сам
  на `localhost:5433` (база, логин и пароль — `dental`).
- `./mvnw verify` — сборка и тесты (Testcontainers, настоящий Postgres).

## Mini App

`src/main/resources/static`: `index.html`, `app.css`, `js/app.js` (экраны), `js/state.js`
(чистые функции: статус строки, даты по Бишкеку — их тесты в `src/test/js`, запуск
`node --test 'src/test/js/*.test.js'`). Без сборки и фреймворка.

- **«День»** — приёмы по времени, у каждого один статус (значок + подпись), лента дней на 3 недели (листается вправо, у дня — число записей, оранжевое — есть заявки), «Сегодня», «📅 Дата» — любой день, ‹ ›.
- **Карточка** — ответ пациента, «Перенести», «Приём состоялся» / «Неявка» (сегодня и раньше),
  «Отменить приём» с плашкой «Вернуть» на 5 с, «Восстановить» у отменённого.
- **«Новая запись»** — поиск пациента или новый, дата, длительность, сетка свободного
  времени (или «Другое время» вручную); «Время занято» — над сеткой, сетка обновляется.
- **Кнопка WhatsApp** в строке и в карточке: ссылка `wa.me` с готовым текстом
  («Здравствуйте, {имя}! Напоминаем: завтра в 09:30 приём у стоматолога…» + `CLINIC_SIGNATURE`)
  собирается в браузере. В том же нажатии — отметка `reminder-opened` запросом с keepalive
  и сразу `openLink` (Telegram открывает ссылки только прямо из нажатия). Отметка не дошла —
  «Не сохранено · повторить».
- **Перерывы и выходные** («Меню → Перерывы и выходные»): каждую неделю (по умолчанию пятница
  13:00–15:00 — 🕌 джума-намаз) или по датам (отпуск), на весь день или с–по, со своим значком.
  Это время вычитается из свободного: у врача в «Дне» — полосатая строка «🕌 Джума-намаз», у
  пациента над сеткой — «С 13:00 до 15:00 — джума-намаз, врач не принимает». Врач сам записать
  в перерыв может («Другое время»).
- **Автонапоминание в бот**: в 18:00 (`PATIENT_REMINDER_TIME`) бот сам напоминает о завтрашнем
  приёме всем, кто записался через бота и ещё не напомнен и не ответил — с кнопками «Приду» /
  «Нужно перенести». Вечерняя сводка в 18:30 их уже считает. `AUTO_REMIND_PATIENTS=false` — выключить.
- **«Записать на следующий визит»** в карточке пришедшего: «Новая запись» с тем же пациентом и
  длительностью, через неделю.
- **Как связаться — выбирает врач.** В карточке приёма: «Напомнить в Telegram» (если пациент
  записывался через бота), «Напомнить в WhatsApp» и «Позвонить». Внутри Telegram `tel:` не работает, поэтому «Позвонить»
  открывает через `openLink` страницу `call.html#<номер>`, а она — звонилку (номер во фрагменте,
  на сервер не уходит). Записавшимся через бота
  быстрая кнопка в строке — синяя «TG», и «Напомнить следующему» шлёт им в бот.
- **Напоминание в бот** отправляет сервер: «Здравствуйте, {имя}! Напоминаем: завтра в 10:00 приём
  у стоматолога…» с кнопками «Приду» / «Нужно перенести». Нажатие сразу ставит ответ в карточке,
  кнопки исчезают, врачу в бот — «Ответ на напоминание: приём …, 10:00 — пациент придёт»
  (без имени). «Ждём ответа» — только после доставки; не доставлено — ошибка, отметки нет.
- **«Завтра»**: «Готово X из N» и главная кнопка «Напомнить следующему (имя, время)» —
  вечерний обход без поиска, кому ещё не написали.
- **Меню** (кнопка в «Дне»): пациенты и лист ожидания, профосмотры, статистика.
- **Позвать на профосмотр**: у кого приём состоялся больше полугода назад и никуда не записан;
  сначала — кого ещё не звали. WhatsApp «пора на профилактический осмотр» отмечает «позвали»
  с датой (`recall_invited_at`), «Записать» — новая запись с этим пациентом.
- **Статистика неявок** по неделям (пн–вс по Бишкеку): не пришли (и %), приёмов, пришли,
  отменено, напомнили, не отмечено; среднее неявок в неделю против «до приложения: 2–3».
- **Пациенты** и **карточка пациента** (нажатие на имя в карточке приёма):
  «Состоялось приёмов: N · неявок: N · отмен: N», «Впереди» и «История», «Записать снова»,
  «Написать в WhatsApp» (пустой чат), «Изменить имя или телефон». Медицинских записей нет —
  до шага 8.
- **Лист ожидания**: «В лист ожидания — хочет раньше» в карточке пациента; список — на экране
  «Пациенты». Окно, куда кто-то из листа помещается (и раньше его приёма), показывает
  «ждут: N»; в записи из него — кандидаты с WhatsApp «Освободилось время…» и «Записать сюда» /
  «Перенести сюда» (уже записанного переносит, не дублирует; из листа убирает сам).
- **«свободно 11:00–12:00»** — окна в рабочих часах (`WORK_HOURS`, `WORK_DAYS`); нажатие —
  запись на это время. Сетку и окна считает сервер тем же условием, что и защита базы.

На ноутбуке: `./mvnw spring-boot:run` → http://localhost:8080. Вне Telegram страница берёт
подписанную тестовую initData у `/dev/init-data` (только профиль `local`), а MainButton
заменяет своя кнопка внизу.

## Браузерные тесты

`e2e/` — Playwright: Chromium открывает Mini App «внутри Telegram» (заглушка
`window.Telegram.WebApp` с подписанной initData, MainButton, BackButton, `openLink`) против
настоящего бэкенда и Postgres. Сценарии: запись и «Время занято», WhatsApp (порядок «отметка →
ссылка», «Не сохранено»), «Напомнить следующему», «Отменить → Вернуть», перенос, ошибки 500 /
401 / 403, карточка пациента, лист ожидания, статистика, профосмотры, самозапись, выбор способа
связи (Telegram / WhatsApp / звонок). В CI — job `e2e`.

На ноутбуке: `./mvnw spring-boot:run`, затем в `e2e/`: `npm ci`, `npx playwright install chromium`,
`npx playwright test`. Тесты чистят локальную базу.

## Несколько врачей

В одном кабинете несколько врачей, у каждого своё кресло (V11, таблица `doctor`):

- **Админ** — Telegram из `ALLOWED_TELEGRAM_IDS` (владелец). «Меню → Врачи»: добавить врача
  (имя, «кратко», Telegram id — врач узнаёт его у @userinfobot), скрыть, фото и профиль.
- **Врач** с привязанным Telegram входит в приложение (кнопка «Открыть день» после `/start`),
  по умолчанию видит свой «День»; вверху — переключатель врачей, чтобы посмотреть коллегу.
- **Права**: свои приёмы врач меняет полностью; чужие — только смотрит («👀 только просмотр»,
  можно позвонить пациенту). Записать, перенести, отменить, отметить, напомнить в чужом
  расписании и задать перерыв коллеге или «всем врачам» — только админ. Проверяет сервер
  (`Staff.requireCanEdit`, 403), Mini App лишь прячет кнопки. Пациенты — общие на клинику.
- **Расписание**: двойная запись запрещена у одного врача (`EXCLUDE ... doctor_id with =`),
  у разных — в одно время можно. Свободное время, лента дней, статистика и оценки — по врачу.
- **Перерывы** — у одного врача или у всех («👥 Все врачи», например джума-намаз).
- **Пациент** выбирает врача первым шагом (фото, имя, «кратко»); врач один — шаг пропускается.
- **Уведомления** — врачу его приёмов. Telegram врача не привязан — админам, первой строкой
  «🧑‍⚕️ Имя врача»; кнопки открывают «День» этого врача (`?doctor=ID`).
- Пациенты, услуги и рабочие часы (`WORK_HOURS`, `WORK_DAYS`) — общие на кабинет.
- После обновления до V11 все прежние приёмы — у врача №1 (имя и фото — из прежнего профиля).

## Адрес и техподдержка

«Меню → О клинике» (админ, V12 `clinic_settings`): адрес, ссылка 2ГИС (сервер принимает только
https-ссылки 2gis.kg / 2gis.ru / 2gis.com / go.2gis.com), Telegram и телефон техподдержки.

- Пациент: карточка «📍 адрес · Открыть в 2ГИС» при записи и в «Ваша запись», внизу —
  «Не получается записаться? 🛟 Техподдержка».
- Бот: адрес и кнопка «📍 Как добраться (2ГИС)» — в подтверждении записи и в напоминании;
  `/help` — телефон клиники, адрес, контакты поддержки; меню команд `/start`, `/help`.
- Врачи: «Меню → Техподдержка» — написать или позвонить и частые вопросы.

## Самозапись пациентов через бота

Посторонний в боте (`/start`) получает кнопку «Записаться на приём». В Mini App (`js/patient.js`):
услуга → день (до 14 дней) → время из сетки свободного → имя → «Поделиться номером»
(`requestContact`: номер приходит боту, сохраняется только свой — `contact.user_id` = отправитель)
→ согласие на обработку данных → «Записаться».

- Заявка (`REQUESTED`) сразу занимает время; врачу в бот — «Новая заявка: вт, 24 окт, 10:00 —
  Осмотр (30 мин)» (без имени и телефона) с кнопкой. В карточке: «Подтвердить» / «Отклонить»;
  пациенту в бот — «запись подтверждена» или «время недоступно».
- Не раньше чем через 2 часа и не дальше 30 дней, только время из сетки, одна запись на человека;
  пациент сам видит и отменяет свою запись, чужие имена и расписание ему не видны.
- **Цены**: у услуги можно указать цену «от» в сомах — пациент видит «от 2 000 сом» на плитке.
- **Профиль врача** («Меню → Мой профиль»): имя, пара слов о себе и фото — пациент видит их,
  когда выбирает врача, и в шапке записи. Фото браузер уменьшает до 800 px (JPEG) до отправки;
  сервер проверяет тип по первым байтам и хранит в базе (`doctor.photo`), отдаёт по
  `/doctors/{id}/photo?v=N` без входа.
- **Отзывы**: на следующий день после приёма (12:00, `REVIEW_TIME`) бот спрашивает тех, кто
  записывался через бота, «Как прошёл приём?» — кнопки 1–5 ⭐. Оценка — в карточке приёма и в
  «Статистике» (средняя за 90 дней), врачу — уведомление без имени. `ASK_REVIEWS=false` — выключить.
- Услуги и их длительность — «Меню → Услуги для самозаписи». Для начала заведены типичные
  (V6: лечение кариеса, чистка, удаление, каналы, брекеты, отбеливание) — длительность поправить
  или ненужное скрыть там же.
- `PATIENT_BOOKING=false` — выключить: посторонние снова видят только контакт клиники.
- **Закон КР:** согласие пациента сохраняется (`patient.consent_at`), но до настоящих пациентов
  нужна регистрация в реестре ГАЗПД (шаг 8).

## Защита от двойной записи

Держит сама база (`V1__init.sql`): ограничение `EXCLUDE USING gist` не даёт двум активным
приёмам пересечься по времени, даже если два запроса пришли одновременно. Интервал
полуоткрытый `[start, end)`, поэтому приёмы встык разрешены. Отменённый приём и неявка
время не занимают.

## API

Ошибки — Problem Details (`application/problem+json`): 422 со списком `errors[]` под полями,
409 с полем `code` — `time-taken` «Время занято», `stale` «Приём изменён, обновите»,
`invalid-transition`, `duplicate-patient` «Такой пациент уже есть».

| Запрос | Что делает |
|---|---|
| `POST /api/patients/search` `{query}` | поиск по части имени или номера (номер не в URL) |
| `POST /api/patients` `{fullName, phone, allowDuplicate}` | новый пациент; телефон приводится к `996XXXXXXXXX` / цифрам E.164 |
| `PUT /api/patients/{id}` `{fullName, phone, allowDuplicate}` | исправить имя или телефон, те же проверки |
| `GET /api/appointments/by-patient/{id}` | карточка пациента: счётчики, будущие и прошлые приёмы |
| `GET /api/appointments/stats?weeks=8` | по неделям: записано, пришли, не пришли, отменено, не отмечено, напомнили |
| `GET /api/appointments/recall?months=6` | кого пора позвать на профосмотр |
| `POST /api/patients/{id}/recall-invited` | кнопка WhatsApp «пора на осмотр» нажата |
| `GET /api/patient/me`, `GET /api/patient/slots?date=&doctorId=&serviceTypeId=`, `POST /api/patient/booking`, `POST /api/patient/booking/cancel` | самозапись: любой, кого подписал Telegram; кто он — из initData |
| `GET/POST/PUT /api/service-types` | услуги для самозаписи (врач) |
| `GET /api/waitlist`, `POST /api/waitlist` `{patientId, durationMinutes}`, `DELETE /api/waitlist/{id}` | лист ожидания |
| `POST /api/waitlist/{id}/book` `{startAt}` | записать или перенести в окно и убрать из листа — одной транзакцией |
| `GET /api/appointments?date=2027-06-01&doctorId=1` | приёмы дня врача по Бишкеку |
| `GET /api/appointments/{id}` | один приём |
| `POST /api/appointments` `{patientId, startAt, durationMinutes}` | запись, 15–240 мин |
| `POST /api/appointments/{id}/reschedule` `{version, startAt, durationMinutes}` | перенос, сбрасывает ответ и отметку напоминания |
| `POST /api/appointments/{id}/status` `{version, status}` | отменить, восстановить, приём состоялся / неявка |
| `POST /api/appointments/{id}/reply` `{version, reply}` | ответ пациента |
| `POST /api/appointments/{id}/undo` `{version, previousStatus}` | «Вернуть» после отмены или неявки |
| `POST /api/appointments/{id}/reminder-opened` | кнопка WhatsApp нажата |
| `POST /api/appointments/{id}/remind-telegram` | напоминание в бот пациенту, записавшемуся через бота; 409 `not-delivered` — не доставлено |
| `GET /api/appointments/counts?from=&days=21` | сколько приёмов в каждый день (без отменённых) и сколько из них заявок — для ленты дней |
| `GET/POST /api/time-off`, `DELETE /api/time-off/{id}` | перерывы и выходные: `{weekday}` или `{firstDay, lastDay}`, `startTime/endTime` (оба null — весь день), `title`, `emoji` |
| `GET /api/appointments/ratings?days=90` | оценки пациентов: количество, средняя, по звёздам |
| `GET /api/doctors`; `GET /api/doctors/admin`, `POST /api/doctors`, `PUT /api/doctors/{id}` | врачи; заводит и привязывает Telegram только админ |
| `PUT /api/doctors/{id}/profile`, `POST/DELETE /api/doctors/{id}/photo` | профиль и фото — сам врач или админ |
| `GET /doctors/{id}/photo?v=N` | фото врача, без входа, кэш на год (адрес меняется с фото) |
| `GET /api/clinic`, `PUT /api/clinic` | адрес, ссылка 2ГИС, техподдержка; менять — только админ |
| `GET /api/slots?date=&doctorId=&duration=&exclude=` | свободные окна дня и сетка начал (шаг 15 мин) в рабочих часах |
| `GET /api/settings` | подпись клиники для текста напоминания |

## Вход и бот

- Каждый запрос к `/api/**` несёт `Authorization: tma <initData>` — строку, которую Telegram
  передаёт в Mini App. Сервер проверяет подпись токеном бота и срок (24 ч): иначе 401
  «Сессия устарела — откройте заново из бота». Подпись верна, но id не в
  `ALLOWED_TELEGRAM_IDS` — 403 с контактом клиники.
- `POST /telegram/webhook` — сообщения боту на сервере; без верного
  `X-Telegram-Bot-Api-Secret-Token` — 401, иначе всегда 200.
- `/start` от врача — приветствие и кнопка меню «Открыть день» (если `PUBLIC_URL` — https);
  от постороннего — «Это служебный бот записи клиники…» и контакт.

- **Уведомления врачу** всем из `ALLOWED_TELEGRAM_IDS` — только числа и время, без имён и
  телефонов (Telegram — сторонний сервис); кнопки открывают нужный экран Mini App:
  - **утро** (`MORNING_DIGEST_TIME`, 09:00): «Сегодня, пт, 23 окт: 5 приёмов, 10:00–17:30.
    Подтвердили: 3 · без ответа: 2», «Завтра…: 8 приёмов, первый в 09:30», «Не отмечено за
    неделю: N»; кнопки «Открыть сегодня» / «Открыть завтра»;
  - **вечер** (`EVENING_DIGEST_TIME`, 18:30): «Завтра не напомнили: 5 из 8», «Сегодня не
    отмечено: 3» — только если есть что сделать;
  - **перед приёмом** (`NOTIFY_BEFORE_MINUTES`, 15; 0 — выключено): «Через 15 мин, в 10:00 —
    приём (30 мин). Пациент подтвердил.» и «Открыть приём» (`/?appointment=ID`). Каждый приём —
    один раз: `UPDATE … RETURNING` по `pre_notified_at`; перенос сбрасывает отметку.

### Бот на ноутбуке

1. `cp .env.example .env` и заполнить: токен от @BotFather, свой id (@userinfobot),
   `TELEGRAM_MODE=polling`. `.env` в `.gitignore`, профиль `local` читает его сам.
2. `./mvnw spring-boot:run` → написать боту `/start`.
3. Кнопка Mini App появится только с https-адресом: туннель (например,
   `cloudflared tunnel --url http://localhost:8080`) и его адрес в `PUBLIC_URL`.

## Деплой

Сервер: DigitalOcean (Германия), 2 ГБ RAM, Docker уже стоит (там работал store). Стек —
`compose.prod.yaml`: Postgres, приложение, nginx (https), certbot (Let's Encrypt). Наружу
открыты только 80 и 443. Память ≈ 1 ГБ по лимитам, поэтому store перед этим выключается.

### 0. Адрес для https

Telegram открывает Mini App только по https с настоящим сертификатом. Домен не нужен:
Let's Encrypt выдаёт сертификаты прямо на IP — `DENTAL_DOMAIN=164.92.189.88`, адрес
`https://164.92.189.88`. Такой сертификат живёт 160 часов; certbot сам продлевает его
на середине срока (`deploy/certbot.sh` проверяет раз в 6 ч). Появится домен — поменять
`DENTAL_DOMAIN` и перезапустить стек.

### 1. Выключить store (только после бэкапа)

```bash
cd /opt/store
deploy/backup.sh && deploy/verify-backup.sh   # свежий бэкап и проверка, что он восстанавливается
docker compose -f compose.prod.yaml --env-file .env down   # без -v: тома с данными остаются
```

### 2. Запустить dental

```bash
git clone https://github.com/subanovkanat321/dental /opt/dental && cd /opt/dental
cp .env.prod.example .env && chmod 600 .env
openssl rand -hex 24   # → POSTGRES_PASSWORD
openssl rand -hex 32   # → TELEGRAM_WEBHOOK_SECRET
nano .env              # DENTAL_DOMAIN, пароли, токен бота, CLINIC_CONTACT
docker compose -f compose.prod.yaml --env-file .env up -d --build
docker compose -f compose.prod.yaml --env-file .env logs -f certbot   # ждать «сертификат … получен»
```

Проверка: `https://<DENTAL_DOMAIN>/actuator/health` → `UP`, в Telegram боту `/start` →
кнопка «Открыть день».

**Один бот на ноутбуке и сервере.** При старте в режиме polling приложение снимает webhook,
и сервер перестаёт получать сообщения. После деплоя на ноутбуке — `TELEGRAM_MODE=off`
(Mini App в браузере работает и так); если webhook всё же снялся —
`docker compose -f compose.prod.yaml --env-file .env restart app` на сервере ставит его заново.

### 3. Бэкап по ночам

```bash
crontab -e
15 3 * * * /opt/dental/deploy/backup.sh >> /var/log/dental-backup.log 2>&1
```

`deploy/verify-backup.sh` — восстанавливает последний бэкап во временный Postgres и считает
строки. До настоящих пациентов (шаг 8) нужна копия вне сервера: `BACKUP_REMOTE` в `.env`
(rclone, как в store).

### Обновление

```bash
cd /opt/dental && git pull && docker compose -f compose.prod.yaml --env-file .env up -d --build
```
